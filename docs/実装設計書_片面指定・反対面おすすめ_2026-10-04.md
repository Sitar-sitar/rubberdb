## 1. 目的・背景

「今使っているフォアはそのままに、バックを選びたい」「バックは決まっているので、フォアを探したい」という選び方に対応する。ユーザー指定は、ラバーの商品IDと使用面の指定と解釈する。厚さ・色・硬度違いなど、現在の商品データにないバリエーション選択は追加しない。

ユーザー確定要件は、片面指定から反対面を推薦できること、既存の両面おすすめを残すこと、まず設計書を作成すること。以下の予算適用、同一製品除外、保存方針は現行実装に合わせた設計上の採用判断である。

## 2. スコープ

## 4. 設計方針・採用判断

| 論点 | 採用 | 代替案と不採用理由 |
|---|---|---|
| 既存機能の保持 | `suggestSet(catalog, conditions)` のインターフェース・結果を維持し、片面指定用の `suggestOppositeSide` を追加 | 既存関数の必須引数変更や推薦順変更は両面の回帰を広げる |
| 初期モード | 常に両面おすすめ。モードと指定IDは画面内stateだけ | 新モードを既定にすると既存利用者に指定操作を要求する |
| 予算 | 両面では従来どおり両面に適用。片面指定では購入候補である反対面だけに適用 | 指定面の価格で拒否したり、2枚合計から予算を差し引くと、手持ちを残す用途と合わない |
| 固定製品 | カタログ内なら廃番・予算外・価格不明も指定可。注意を表示 | 新規購入候補の除外規則を指定品にも適用すると手持ちの廃番品を利用できない |
| 反対面の同一製品 | 指定IDを除外して推薦 | 現行の異なる2枚という契約を維持する。同一製品両面設定は別スコープ |
| 相性の説明 | 反対面の役割・経験・予算に基づく推薦であることを説明 | 相性点の根拠がないため、最適な相性や性能向上を保証する表現は採用しない |
| 保存 | 現行 .v1 の実際の2枚と条件だけを保存。固定モードは永続化しない | 今回は保存スキーマを拡張しない。モード復元のための .v2 移行は別機能として扱う |

## 5. 詳細仕様

### 5.1 診断方法と指定面の入力

`recommend.ts` に `DiagnosisMode = "both" | "fixedFore" | "fixedBack"` と `Side = "fore" | "back"` を定義する。Homeは `mode`（初期both）、`fixedRubberId: string | null`（初期null）、指定製品検索文字列（初期空）を保持する。状態を別々のフォア固定・バック固定IDに分けず、現在の指定1枚だけを持つ。

診断セクションの既存質問より前に、ラベル「診断方法」と3つの選択ボタンを置く。選択状態は既存ChoiceButtonと同様にaria-pressedで伝える。片面指定モードのみ、指定面を明示した製品選択欄を出す。

- 検索inputのラベルは「指定するラバーを検索」。商品名とブランドをtrim・小文字化して部分一致する。既存のカタログ検索stateと共有しない。
- 選択はラベル付きnative select（「フォアに使うラバー」または「バックに使うラバー」）を使用する。先頭は「ラバーを選択してください」、値は空。各optionはブランド・商品名・廃番注記を含め、IDをvalueにする。
- 選択候補は全カタログ。検索結果はブランド文字列、商品名の日本語順、最後にASCII ID順で安定整列する。推薦のrankにはこの表示順を渡さない。
- 検索0件は「一致するラバーがありません」と検索条件を消す操作を表示。選択済み製品が検索結果外になってもそのoptionを残し、選択カードで商品名を表示する。検索入力だけでは固定IDを変更しない。
- 選択製品カードから既存詳細モーダルを開ける。自由記述のID入力や、一覧先頭製品の自動選択はしない。
- フォア・バックの役割質問、経験、利き手は両モードで残す。固定面の役割欄には「この面の役割は説明用です。指定した製品は変わりません」と付記する。
- 予算ラベルは両面で「片面あたりの予算」、片面指定で「おすすめする面の予算」。片面指定の注記は「指定したラバーには予算制限を適用しません。おすすめする面は、予算指定時に価格未公表の製品を除きます」。

### 5.2 片面指定推薦の関数契約

新規純粋関数 `suggestOppositeSide(catalog: Rubber[], conditions: SetConditions, fixed: { side: Side; rubberId: string | null }): OppositeSideSuggestion` を `recommend.ts` に追加する。外部通信・保存・カタログ変更は行わない。`rank`、`sideScore`、`withinBudget`、`comparisonAlternatives` を共用する。

戻り値はstatusによる判別共用体とし、次の形を採用する。

| status | 必須情報 | 意味 |
|---|---|---|
| awaitingSelection | fixedSide | nullまたは空ID。選択を待つ |
| invalidFixed | fixedSide、fixedRubberId | 非空IDがカタログにない。別製品へ代替しない |
| insufficient | fixedSide、fixedRubber、recommendedSide、candidateCount（0）、除外件数 | 指定品は有効だが反対面候補がない |
| ready | fixedSide、fixedRubber、recommendedSide、fore、back、recommendedList、recommendedAlternatives、recommendedTopTieCount、除外件数 | 固定品と推薦品の2枚が成立 |

全ての有効指定結果（insufficient/ready）には `fixedDiscontinued: boolean`、`fixedPriceUnknown: boolean`、`fixedOverBudget: boolean` を持つ。最後の値は価格既知かつ有限予算を超える場合のみtrue。価格不明を予算超過と扱わない。除外件数の名前は既存と同じ `excludedUnknownPriceCount` / `excludedDiscontinuedCount` とし、以下の母集団を明示する。

処理順:

1. 指定IDを検証してcatalogから固定品を取得する。取得できなければ上記の待ち／不正状態を返す。
2. 反対面の母集団は `catalog` から指定IDを除いた製品。固定品は廃番・価格不明の除外件数に数えない。
3. 母集団の廃番を除外し、その件数を `excludedDiscontinuedCount` にする。有限予算の場合は残った母集団の価格null件数を `excludedUnknownPriceCount` にする。freeでは0。予算超過だけの製品はこの2件数に含めない。
4. `withinBudget` で絞る。候補0件ならinsufficient。1件以上ならreadyになれる（両面推薦の2件条件を流用しない）。
5. 固定side=foreならbackRole、固定side=backならforeRoleでrankする。最大得点を選び、同点はASCII ID昇順。固定面の役割、固定品の性能、利き手は反対面の順位に影響しない。
6. `fore` / `back` は面を入れ替えず組み立てる。指定面はcatalogから取得した指定品と同じIDのまま。
7. `recommendedList` は反対面候補全体の順位順。`recommendedTopTieCount` は主推薦と同じ得点の件数（主推薦自身を含む）。比較候補は選択2枚のIDを除き、既存comparisonAlternativesで最大3件。

空catalog、指定品だけのcatalog、指定品が廃番で他に現行品1件、指定品が予算外で他に予算内1件をそれぞれ扱う。カタログの一意ID・性能値等は既存データ検査を前提にし、新関数でも入力配列を変更しない。

### 5.3 再計算・状態遷移

計算は既存と同じ同期useMemo。通信・待機スピナー・リトライ・非同期応答の競合は追加しない。片面指定時は両面関数の結果を流用せず、専用結果を描画する。UI用の面別表示情報はHomeで組み立て、既存SetSuggestionの型へ偽装しない。

| 操作 | 必須遷移 |
|---|---|
| 初回表示／ページ再読込 | both、指定ID=null、既存5条件の初期値。保存データは従来どおり読み込む |
| bothから片面指定へ | 5条件を保持、固定ID=null、検索空、pinnedSet=null、比較を閉じる。指定待ち表示 |
| fixedForeとfixedBackの相互切替 | 5条件と指定IDを保持。同じ製品を新しい指定面に移す。検索空、pinned解除、比較を閉じて反対面を再計算 |
| 片面指定からbothへ | 5条件を保持、指定ID=null、検索空、pinned解除、比較を閉じ、既存suggestSetで再計算 |
| 現在選択中のモードを再度押す | 状態を変えない。指定を消さない |
| 指定製品変更／選択解除 | IDを更新／null、pinned解除、比較を閉じる。変更後の結果だけを表示 |
| 役割・経験・予算変更 | 固定IDを保持、pinned解除、比較を閉じる。固定面は変えず反対面を再計算 |
| 利き手変更 | 両面モードは従来どおり説明だけ変更。片面指定でも順位・固定IDを維持し、保存セット再確認中は元2枚の表示を維持 |
| 製品検索文字列変更 | 固定ID・結果・pinnedを変更しない |
| 最初から選ぶ | mode=both、固定ID=null、検索空、5条件を既存初期値へ戻し、pinned解除・比較閉じる |

### 5.4 結果・例外表示

readyでは2枚の位置を現行のフォア／バックのまま表示する。固定面に「あなたが指定」、反対面に「おすすめ」を付け、色だけに頼らず判別できるようにする。固定面の推薦理由文は「この面は指定したラバーです」に置換し、採点による推薦と誤認させない。

結果の説明に「反対面の役割・経験・予算から選んでいます。ラケットや厚さまで含めた相性を判定するものではありません」を追加する。既存の性能点数がサイト内目安である説明も維持する。

- 同点注記と比較欄はおすすめ面のみ。固定面の同点数や代替品一覧を生成・表示しない。候補1件なら比較ボタンを出さず「ほかの候補はありません」を表示する。
- awaitingSelectionは「フォアに使うラバーを選ぶと、バックのおすすめを表示します」（逆の場合は面を反転）。2枚の結果・セット価格・保存・比較を表示しない。
- invalidFixedは「指定したラバーが見つかりません。ラバーを選び直してください」。固定品が消えたとき古い結果を残さない。
- insufficientは固定カードを残し、「バックの条件に合うラバーがありません」（逆はフォア）と「おすすめ候補0件」を表示。予算変更・指定品の選び直し・カタログへの導線を表示し、2枚価格・セット保存・比較は表示しない。
- 有効な廃番指定には「指定品は廃番です。手持ちの使用を想定しています。購入する場合は在庫を確認してください」。反対面へ廃番を推薦しない。
- 固定価格不明には「指定品の価格は未確認です」、予算超過には「指定品は選択予算を超えています。予算はおすすめする面だけに適用しています」を表示。
- 2枚価格は現行 `calcSetPrice` / `setPriceHeadline` / `setPriceNote` をそのまま使用。手持ち品を含む2枚の参考額であることと、今回購入する反対面の税込参考価格を分けて表示する。freeの価格null推薦は「価格未確認」。ダミー価格・不明価格を0円扱いする表示は禁止。

### 5.5 保存・再確認の互換性

セット保存対象は表示中の実際のfore/backと5条件。`SavedSet`、.v1キー、ID生成式、createdAtの形式は変えない。両面と片面指定で同じ2枚・条件なら同じ保存セットとして扱う。移行・バックフィル・新規保存キーは不要。既存お気に入りラバーの読み書きも維持する。

固定モードと指定面は保存しない。この制限を片面指定の保存ボタン付近で「2枚の組み合わせと条件を保存します。片面指定の設定は保存されません」と明示する。

`restoreSet` はmode=both、固定ID=null、検索空、保存された5条件へ復元し、現行のpinnedSetで保存時の実際の2枚を表示する。両面モードへ戻ったことは「保存した組み合わせを表示しています。診断方法は両面おすすめに戻ります」と説明する。保存表示では指定／おすすめバッジを付けず、各カードを「保存したラバー」とする。

保存再確認と現在推薦を区別する。pinnedSetがある間は、現在の候補の比較・同点情報を表示しない。現在結果とIDが一致する場合も同様にする。「現在の提案を見る」を常に表示し、解除時はbothの最新suggestSetへ戻す（候補不足なら不足表示）。元の2枚・価格・廃番注意は不足でも再確認できる。削除は既存IDで行う。

保存不可の場合に画面内利用を続ける現行挙動、破損JSON・不正要素の破棄、カタログにない保存IDのpruneを変更しない。推薦設定の永続化が将来必要になった場合だけ、別設計で版付きスキーマと旧データ移行を定義する。

### 5.6 アクセシビリティと表示幅

モードgroup、検索input、製品select、結果の各面に日本語の名前を付ける。native selectはキーボードで操作可能とし、検索0件でも操作欄を消さない。指定待ち・不正・候補不足と推薦製品名の短い要約をpoliteなstatus領域で通知し、結果全体を読み直させない。検索件数は別の短いstatusで知らせる。

自動再計算ではフォーカス移動・自動スクロールをしない。詳細モーダルのEscと起点復帰を維持する。保存再確認スクロールは既存のprefers-reduced-motion対応を維持する。モードでselectが消える操作後はモードボタンにフォーカスが残る。

幅375pxと1280pxで選択欄・長い製品名・注意文・結果が横にはみ出さないこと。片面指定の比較は1列を基本とし、固定面の空の比較列を残さない。既存の診断・図鑑・ガイドの導線は維持する。

## 6. 既存機能の非破壊条件

1. 初期表示とbothの全54条件で、採用2枚・上位候補・同点数・比較候補が基準コミットのスナップショットと同じ。今回の実装を理由に既存スナップショットを更新しない。
2. bothの予算・価格不明・廃番除外と候補2件未満の不足は従来どおり。片面モードの候補1件readyと混同しない。
3. 詳細モーダル、カタログ検索、お気に入りラバー、旧保存セットの元2枚復元、ID保持を維持する。
4. 採点・製品データ・公式出典・保存スキーマを変更しない。公開URL・base・配信方式を維持する。
5. .v1を維持するため、機能撤回後も新機能で保存した組み合わせを既存版から再確認できる。

## 8. テスト・検証

### 8.1 純粋関数

- 固定fore/backの両方向で指定IDが結果の該当面と一致し、反対面は異なるID、予算内、非廃番、最大sideScoreとなる。同点はASCII ID順。
- null／空ID／未登録ID／空catalog／固定品しかないcatalog／候補0件／候補1件／候補複数を小さなfixtureで検証。候補1件ではreadyで比較空・同点数1。
- 指定品が廃番・価格null・予算上限超過でも保持。反対面はそれぞれの制約を守る。6,000円・8,000円の等値と1円超過、freeで価格nullを検証。
- 固定面の役割だけを変更して反対面の結果が変わらない。反対面の役割・経験・予算変更は反対面へ反映する。
- 固定IDが廃番・価格nullでも除外件数に含まれない。母集団内で廃番かつ価格nullの製品は廃番件数のみ。有限予算とfreeの件数差を確認。
- catalogの逆順・複数並べ替えでも結果全体が一致し、元配列が変更されない。比較最大3件・重複なし・選択2枚除外・得点順維持・同点内ブランド巡回を確認。
- 公開catalogの全指定ID×指定面2方向×反対面役割3種×経験2種×予算3種を走査する。fixed面役割は固定して走査し、役割独立性は別ケースで検証。状態に応じた固定ID・予算・廃番・最高点不変条件を検査する（全件readyは要求しない）。
- 両面の既存54条件スナップショットと従来の順位・不足テストを更新なしでpassさせる。

### 8.2 画面・保存

- 初期both、固定fore未選択、固定back未選択、選択後ready、選択解除、3モード切替、同じモードの再押下、resetを実操作イベントで検証する。
- 固定製品の検索0件・検索範囲外でも選択維持、カタログ検索との独立、selectの名前とキーボード操作を確認する。
- 固定面の役割・経験・予算変更後も固定IDが残り、候補なしでは古いおすすめや保存ボタンが残らない。比較はおすすめ面のみ。
- 廃番／予算外／価格不明の指定の注意文、2枚価格と反対面購入価格、不明価格の表示を確認する。
- 新片面結果を保存→localStorage再読込→元2枚と条件を復元→bothへ戻った説明→現在の提案を見る→削除。保存にモード属性や新キーを追加していないことを確認する。
- 旧.v1廃番セット、復元時に現在候補不足、復元2枚が現在推薦と同じ場合もpinned表示と比較非表示を確認する。破損JSON・無効要素・保存不可・不存在IDの既存テストを維持する。
- 両面の既存5質問に加え診断方法groupが名前・選択状態を公開する。モーダルEsc復帰と検索statusの既存テストは新status領域を区別して更新する（単一statusがある前提を外す）。

### 8.3 実装時の検証コマンド・実機確認

PowerShellで `pnpm check`、`pnpm test`、`pnpm report:recommendations`、`pnpm exec vite build --base /rubberdb/`、`node scripts/verify-build-artifact.mjs dist/public --base /rubberdb/ --max-js-kb 390 --max-css-kb 60` を実行する。390/60はKiB換算の受入上限とする。成果物検査の既定JS上限400を引き上げず、本機能も先行版の390以下を維持する。起動制約による未実行と対象テスト失敗を分けて記録する。

Chromeでローカル実装画面を375px/1280px、キーボードで確認する。3モード、両方向の固定保持、廃番・価格不明、比較、保存再読込、初期化、詳細モーダルを実操作する。実際の読み上げとOSの動作軽減設定も確認し、未実施なら受入未達として記録する。先行リリースの実機未確認に対する承認を、本機能の受入承認へ流用しない。

## 10. リスク・ロールバック

| リスク | 予防・検出・回復 |
|---|---|
| 共通化で両面結果が変わる | 既存suggestSet契約を維持し54条件無差分を必須化。差分が出たら原因を直し、スナップショット更新で吸収しない |
| 指定品が意図せず変わる | fixedIDを独立保持、全遷移テスト。無効IDでは再選択を要求し自動置換しない |
| 固定面も予算内と誤認 | 予算ラベルと固定注意、2枚参考額と反対面価格を分離。指定面の値で推薦を拒否しない |
| 保存モードが消えたと感じる | 保存前と復元後に制限説明。実際の2枚・条件は保持し、モード保存は別設計 |
| 同点や採点を相性の実証と誤認 | サイト内目安・役割条件による選択支援を明記し、相性加点をしない |
| 静的配信の反映遅れ | 公開hashと操作を確認。未一致を成功扱いせず待機または配信状態を調査 |

実装前に基準コミットと検証結果を記録する。公開前は機能差分を取り下げて既存版へ戻す。公開後は実装コミットをrevertして既存の検証・Pages経路で再公開し、公開hashと両面操作を確認する。履歴の強制変更やlocalStorageの削除をしない。.v1形式が同じため新機能で保存したセットも旧版で読み込め、データ移行の巻き戻しは不要。
