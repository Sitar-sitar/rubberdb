## 1. 目的・背景

推薦の種類が少ないことだけでは不具合と判定できない。現在の採点には製品差を表す根拠が限られており、表示製品数を増やすために点数や性能値を調整すると推薦品質を悪化させる。本バッチでは、順序依存を除き、同じ評価の候補を比較できることと、採点の限界を説明できることを達成する。

製品情報は確認できた事実と未確認を区別する。廃番が確認された製品は新規推薦から外すが、既存カタログと利用者の保存データには残す。診断はキーボードと読み上げでも選択状態が分かるようにする。

## 4. 設計方針と採用判断

| 判断 | 採用 | 採用しない案と理由 |
|---|---|---|
| 同点 | 得点降順、同点は不変IDのASCII昇順。代表を出し、同点候補があることを表示 | ランダム/日替わりは再現できず、ブランド順は記載順の優遇を残す |
| 比較表示 | 同点群の中だけブランドを交互にする。低得点を高得点の前へ出さない | ブランド数のノルマや減点は適性より分散を優先してしまう |
| 合格指標 | 順序不変、最高得点採用、同点比較の到達性、推薦理由の説明 | 「13製品をN製品に増やす」は品質保証にならず、ノルマを設けない |
| 原産国 | メーカー公式の製品単位の製造国。根拠が無ければ未確認 | ブランド所在地や粘着性から推測しない。ゴム/スポンジ別の国を製品全体の国へ合成しない |
| 廃番 | `discontinued?: boolean`、trueだけを診断から除外。IDは保持 | ページ消失を廃番扱いしない。IDの台帳から消さない |
| 読み上げ | 既存buttonに `aria-pressed`、名前付きgroup。標準のTab/Enter/Space操作 | `radiogroup` のroleだけを足す案は矢印キー等の追加実装が必要になる |

これらは今回の技術上の採用案であり、ユーザーが個別の採点方式や原産国を指定した事実とは区別する。推薦の妥当性を全面的に再評価したという主張はしない。

## 5. 詳細仕様

### 5.1 R-01：推薦順位と比較候補

`sideScore`、`BUDGET_LIMITS`、`withinBudget`、`beginnerPricePenalty` の式は変更しない。推薦対象は `discontinued !== true` かつ予算を満たす製品。typeによる新しい除外は導入しない。

1. フォア候補を得点降順に並べ、同点はIDのASCII昇順（文字列の `<` / `>` による比較。locale依存の比較は使わない）。先頭をフォアに選ぶ。
2. バック候補は同じ候補集合から選ばれたフォアIDを除き、バック条件で同じ比較を行う。先頭をバックに選ぶ。
3. `foreList/backList` は全候補の順位として保持する。同点注記の件数はそれぞれの先頭得点と等しい製品数。フォアを除いた後のバック集合で数える。
4. 比較欄用に `foreAlternatives/backAlternatives` を別途返す。選ばれた2枚のIDを双方の比較欄から除いた後、得点が等しい群ごとにブランド別のキューを作る。各キュー内はID昇順、キューの順序は先頭ID昇順。各ブランドから1件ずつ取り出す巡回を繰り返し、その群を使い切ってから次の得点群へ進む。先頭3件を表示する。
5. 主推薦は常にその面の最高得点。ブランド交互表示が主推薦の選択に影響することはない。点数はサイト内の目安で、公式の性能順位ではないことを結果欄に短く明記する。

比較欄の各項目には「同じ評価の候補」（主推薦と同点）または「次の候補」（低得点）を表示する。主推薦に同点があれば「同じ評価の候補が他にN件あります。表示中の製品はその中の一例です」と表示。IDの内部仕様はUIに出さず、READMEで順位決定規則を説明する。

`SetSuggestion` は §5.2 の判別可能な結果型に変更する。成功時に上記リストと件数を含める。既存 `excludedUnknownPriceCount` は廃番除外後の対象内で数える（予算freeでは0）。廃番除外件数は別の `excludedDiscontinuedCount` にする。

### 5.2 R-02：不足状態・保存セットとの関係

結果型は `status: "ready" | "insufficient"` で区別する。ready は fore/back が必須。insufficient は `candidateCount` と除外件数を持ち、fore/backを持たない。0件・1件で `catalog[0]/[1]` を返すフォールバックは削除する。

| 状態 | 画面・遷移 |
|---|---|
| 通常、候補2件以上 | 2枚と価格・比較候補を表示。セット保存可能 |
| 通常、候補0/1件 | 「条件に合う製品が2枚そろいません」と該当件数。2枚の価格・保存・比較のボタンは出さず、予算選択とカタログへの導線を表示 |
| 保存セットを復元 | `pinnedSet` のIDで2枚を表示。廃番でも表示する。現在の推薦が不足していても保存表示を優先する |
| 保存の2枚と現在の提案が相違、または現在の提案が不足 | 保存時の2枚である注記と「現在の提案を見る」。比較欄は表示しない（別の2枚を基準にした比較になることを防ぐ） |
| 「現在の提案を見る」/役割・経験・予算を変更/リセット | pinnedSetを解除し、readyまたはinsufficientへ。利き手だけの変更では固定を保つ |

`resolveDisplayedSet` は成功推薦またはnullとpinnedSetを受け、保存IDが解決できればその組を、次に成功推薦を採用し、どちらも無ければnullを返す。`Home` はnullを判定してから価格とセットIDを計算し、不足中にundefinedを参照しない。

localStorageキー、SavedSet形状、セットIDの生成式は変更しない。保存の重複判定は従来式を維持する。廃番追加はカタログからの削除ではないため `pruneFavorites` の既知ID集合には廃番も含む。再確認・削除・ラバーの保存は廃番でも可能。

### 5.3 D-01：原産国と検証台帳

runtimeの `country?: string` を維持し、未確認は属性を省略する。空文字や「未確認」を値として入れない。モーダルには常に「原産国」を出し、値が無ければ「未確認」。フリーテキスト検索へ原産国として含める値は確定した `country` のみ。公式説明・用途など既存の検索対象も保持するため、「中国」の検索結果には説明文で一致した製品も含まれ、原産国確定件数とは一致しない。画面には「原産国は詳細で確認できます。未確認の製品もあります」と記載し、国だけで絞り込むフィルタは本バッチで追加しない。

実装時に `docs/data/product-verification.json`（新規、ブラウザにimportしない）を作り、全カタログIDに1レコードを持たせる。台帳は調査証拠、runtimeは表示値であり、テストで同期を検査する。

- root: `{ schemaVersion: 1, products: [...] }`。
- 各レコード: `id`、`country`、`discontinued` の3キー。
- country: `{ status: "confirmed" | "unconfirmed", value: string | null, checkedAt: "YYYY-MM-DD", sources: string[], note: string }`。
- discontinued: `{ status: "confirmed" | "unconfirmed", value: true | null, checkedAt: "YYYY-MM-DD", sources: string[], note: string }`。
- confirmedはnon-emptyのsourcesが必須。countryのvalueは実際に明記された製造国を日本語の同一表記へ正規化。複数の製造国が製品全体に明記されていれば「日本 / ドイツ」のように五十音順で結合する。部材単位だけの記載はunconfirmedにする。
- unconfirmedはvalue=null、理由をnoteへ記載。sourcesには実際に確認した公式ページを記録する。到達できなければ空配列も許可し、その理由を記録する。checkedAtは確認を試みた実日付（JST）とし、初期値で未来日を埋めない。
- status/valueの組み合わせ、IDの一意性、カタログとの完全一致、sourcesの重複なし、noteの非空、checkedAtの暦として有効な日付とJST当日以前を検査する。日付テストには固定した時計を使い、誤日付・未来日をfixtureで検出する。新規製品はruntime、公開ID台帳、調査台帳を同じ変更に含める。

全159件を確認する。既存13件も監査対象。製品単位の根拠が確認できない既存countryは省略へ変更し、変更理由を台帳に残す。146件を推測で埋めて完了扱いにしない。情報がない製品・公式ページへ到達できない製品は、調査結果と理由を記録したunconfirmedで完了可能。全件の調査を試みていない状態は完了不可。

情報源はブランドの `brandHosts` に含まれる公式httpsページまたはその公式PDF。別の公式ホストが必要なら所有者を確認して `brands.ts` に追加し、根拠をnoteに記録する。販売店、口コミ、ブランドの本拠地は原産国の証拠にしない。引用は国名・廃番告知の要旨に留める。URLはJSONの証拠値として保存する。

原産国だけの調査で既存 `verifiedAt`（価格・仕様等の確認日）を更新しない。モーダルの原産国の確認日はruntimeへ追加しないが、公式製品リンクは維持し、詳細証拠は台帳で追える。READMEに2種類の確認日の意味を記載する。

### 5.4 D-02：廃番と既存データ互換性

`types/rubber.ts` のRubberへ `discontinued?: boolean` を追加する。省略は「廃番を確認していない」であり、「現行品を公式確認した」の意味にしない。公式の廃番・生産終了告知が製品に対応すると確認できた場合のみtrue。告知が曖昧、販売店の在庫切れ、ページの404はunconfirmed。

- 台帳discontinued.confirmed/value=true と runtime.discontinued=true を双方向に一致させる。unconfirmedではruntime属性を省略する。falseは記載しない。
- trueの製品は新規推薦と中国製ガイドから除外する。ガイドの固定IDは台帳から削除せず、フィルタ後0件の区分は説明「掲載候補は現在ありません」を表示し、補充のための架空データを作らない。
- カタログ件数・並び順と検索には廃番も含める。カード、詳細、保存ラバー、保存セットの各面にテキスト「廃番（生産終了を確認）」を付ける。色だけに依存しない。該当セットには「購入前に在庫を確認してください」を表示する。
- 公開済みIDは永久に台帳とカタログに残す。`publishedIds.json` の削除を廃番処理として認めない。廃番の取り消しは、公式の再生産等が確認できたときにruntimeのtrueを除去し、台帳をunconfirmedへ戻してnoteに再開の証拠を残す。
- 全候補が廃番でも §5.2 の不足表示で終了する。廃番から代用品を勝手に選ばない。

公式告知が見つからなければ本バッチでtrueが0件でもよい。表示・保存・不足経路の検証は仮の製品fixtureで行い、本番データに架空の廃番を入れない。

### 5.5 A-01：選択・開閉・検索のアクセシビリティ

- `SelectPill`、`ChoiceButton` は `aria-pressed={active}`。`RoleGrid` のbuttonは `aria-pressed={value === option.id}`。選択済みのbuttonを再押下しても解除しない（各群で常に1件選択）。
- 利き手、フォア、バック、経験、予算の5群に `role="group"` と見えるラベルを指す `aria-labelledby` を設定。ラベルIDは各群で一意とする。Tabで各buttonへ移動し、Enter/Spaceで選択。独自の矢印キー制御は導入しない。
- セット保存と詳細モーダルのお気に入りは `aria-pressed` を現在値に同期する。状態で文言が変わる既存仕様を保持する。
- 候補開閉buttonに `aria-expanded` と、比較領域の安定したIDを指す `aria-controls`。閉じている領域はDOMにhiddenで残す（参照先を維持）。保存表示で比較不可のときはbutton・領域の両方を出さない。
- カタログのinputと2つのselectに、それぞれ「ラバー検索」「ラバーの種別」「ブランド」のlabelを関連付ける。検索結果件数だけを `role="status"` / `aria-live="polite"` の更新対象にし、カード全体をlive領域にしない。
- 選択後に結果欄へ自動フォーカス移動しない。保存セットの復元では既存のスクロールは保ち、押下したbuttonにフォーカスを残す。モーダルのtrap/Esc/起点への復帰は保持する。
- `index.css` に識別できる共通の `:focus-visible` を追加（3px outline、2px offset）。既存 `outline-none` より優先して描画されるようにし、通常時のoutlineを全て消す変更をしない。
- `prefers-reduced-motion: reduce` ではhtmlのsmooth scrollをautoにし、復元時の `scrollIntoView` もmatchMediaでautoを選ぶ。モーダルの既存 `motion-safe` は保持する。
- ボタンの見た目、配色、モーダル配置、レスポンシブ構成は保持し、追加注記が320px幅でも横にはみ出さないよう折り返す。

## 6. 既存機能の非破壊条件

- 公開済み159 ID、ブランド順、カタログの元の並び順を保持。除去対象は廃番の推薦・ガイドだけ。
- ID・名前・価格・type・硬度・styles・性能値・suitableFor・officialNote・source・verifiedAtは変更しない。countryの公式確認による補正とdiscontinuedの追加だけを認める。公式ホスト追加は証拠付きで別差分にする。

## 10. リスク・公開・ロールバック

主推薦のIDによる同点決着も代表の選び方であり、製品の適性を証明するものではない。39/108面の基準値と新結果を記録し、同点注記で限界を伝える。実打根拠のない係数調整は本バッチで行わない。

原産国/廃番の誤認は製品案内に影響する。公式の製品単位の証拠、台帳との一致、変更差分で検出する。情報が相反する場合はunconfirmedにし、根拠が確定するまで値を出さない。

公開指示を受けたら対象HEAD、CI run、Pages run、配信HTMLのアセットハッシュとbaseを確認し、公開URLでも同点注記・選択・検索・モーダル・保存復元を実操作する。同一バンドルのHTTP確認だけでブラウザ操作を代替しない。現在URLのヘッダー確認を行う場合は、その日付とURLをPhase 4へ記録し、Phase 1の当時記録は保持する。

不具合時は本バッチの実装コミットをrevertし、既存v1.1.2相当を再ビルド・再公開する。原産国や廃番の修正は該当データと台帳を一緒に戻す。スキーマ移行・ID削除・localStorageの消去が無いため、v1.2.0で保存したセットはv1.1.2でも同じ2IDと条件を読める。旧版では廃番の推薦除外と表示が失われる点を記録する。公開操作は公開指示の範囲で実施する。
