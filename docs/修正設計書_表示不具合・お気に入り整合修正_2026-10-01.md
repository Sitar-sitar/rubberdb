## 3. 全体方針

- **画面層のロジックは純粋関数へ出してからテストする。** テスト環境は `node`（DOM なし）のままにし、React コンポーネントのテスト基盤は入れない。
- **`Home.tsx` は先に整形だけのコミットを作る。** 現状は 148 行に 47 KB（1 行最大 4,793 文字）が詰まっており、このままでは修正差分が読めない。整形のみのコミットと修正コミットを分け、整形コミットは `git diff -w` とビルド成果物のサイズで挙動不変を確認する。
- **未定義トークンは「定義を足す」のではなく「使わない」方へ寄せる。** サイト全体が 16 進の直接指定で統一されているため、エラー画面と 404 画面もそれに合わせる。shadcn 由来のトークン一式を足す案は、使う箇所が 2 画面しかなく過剰なので採らない。
- **保存セットは「保存した 2 枚」を正とする。** 再確認は保存時の組み合わせを表示し、現在の提案と違う場合はその旨を示す。条件から再計算する現挙動は、保存の意味（あとで見返す）と合わない。

## 4. 詳細仕様

### BUG-01 役割ラベル

- `client/src/utils/roles.ts` を新設し、`Home.tsx` の `foreOptions` / `backOptions` を移す。
- `roleLabel(side: "fore" | "back", role: Role): string` を同ファイルに置く。`side` に応じた配列だけを検索する。
- 呼び出し箇所をすべて side 付きへ直す：結果欄の説明文、`SetCard` の `role`、`AlternativeList` の `role`、`setDetail` に渡す `role`、`FavoriteSets` の「フォア：… / バック：…」。
- 期待値：

| role | fore | back |
|---|---|---|
| `spin` | 回転ドライブ | 回転でつなぐ |
| `counter` | 早い攻撃 | 早い攻撃 |
| `control` | 安定してつなぐ | 安定ブロック |

### BUG-02 保存セットの再確認

- `Home` に `pinnedSet: { foreId: string; backId: string } | null` の state を追加する（初期値 `null`）。
- `restoreSet` は従来どおり条件（利き手・役割・経験・予算）を復元したうえで、`pinnedSet` に保存済みの `foreId` / `backId` を入れる。
- 表示する 2 枚は純粋関数 `resolveDisplayedSet(suggestion, pinnedSet, catalog)`（`client/src/utils/favorites.ts`）で決める。
  - `pinnedSet` があり、両 ID がカタログに存在する → その 2 枚を返し、`pinned: true`。
  - それ以外 → `suggestion.fore` / `suggestion.back` を返し、`pinned: false`。
- `pinnedSet` を解除するタイミング：フォア役割・バック役割・経験・予算のいずれかを変更したとき、「最初から選ぶ」を押したとき。利き手の変更では解除しない（ラバーの選定に影響しないため）。
- `pinned: true` かつ表示中の 2 枚が現在の提案と異なる場合、結果欄に 1 行の注記と解除ボタンを出す。
  - 文言：「保存したときの組み合わせを表示しています。現在のデータでは提案が変わっています。」／ボタン「現在の提案を見る」（`pinnedSet` を `null` にする）。
- `currentSetId`・合計価格・保存ボタンの状態は、表示中の 2 枚から算出する（現行と同じ式）。これにより、再確認直後は「保存済みのセット」と表示される。
- 「ほかの候補も比べる」の一覧は、現在の提案（`foreList` / `backList`）のままとする。

### BUG-03 カタログに無い ID の扱い

- 純粋関数 `pruneFavorites(rubberIds, sets, catalogIds)` を `client/src/utils/favorites.ts` に置く。
  - ラバー：カタログに存在する ID だけを残す。重複 ID は先勝ちで 1 件にする。
  - セット：`foreId` と `backId` の両方がカタログに存在するものだけを残す。
- `Home` の `useState` 初期化で、`loadFavoriteRubberIds()` / `loadFavoriteSets()` の結果へ `pruneFavorites` を通す。既存の保存用 `useEffect` により、整理後の内容が localStorage へ書き戻る。
- これで件数表示（ヘッダー、`SAVED SETS / n`、`SAVED RUBBERS / n`）と一覧の件数が一致する。`FavoriteSets` 内の `if (!fore || !back) return null` は防御として残す。
- この方針は「ID が消えたお気に入りは読み込み時に削除される」ことを意味する。前回設計 ROB-01 の「壊れた保存データは破棄する」と同じ扱い。採否は §10-1 で確認する。

### BUG-04 フッターの公式ソース

- `sources.slice(0, 6)` を `sources` に変える（全 11 件を表示）。
- 件数が増えるため、既存の `flex-wrap` で折り返すことを実機で確認する。レイアウト変更はしない。

### BUG-05 モーダルのアニメーション

- `client/src/index.css` に `@keyframes slideIn` を追加する：`from { transform: translateX(24px); opacity: 0 }` → `to { transform: none; opacity: 1 }`。
- 既存の `motion-safe:` 指定はそのまま使う（動きを減らす設定の利用者には適用しない）。
- `scripts/verify-build-artifact.mjs` に検査を 1 つ足す：成果物の CSS に `slideIn` を参照する `animation` があるのに `@keyframes slideIn` が無ければ NG。

### BUG-06 エラー画面・404 画面

- `ErrorBoundary.tsx`：未定義クラスをサイトの既存色へ置き換える。
  - `text-destructive` → `text-[#d54a3e]`、`text-muted-foreground` → `text-[#68788a]`、`bg-muted` → `bg-[#edf4fa]`。
- `NotFound.tsx`：`Card` / `Button` を使わず素の要素で書き直し、日本語にする。
  - 見出し「404」／「ページが見つかりません」／本文「お探しのページは移動または削除された可能性があります。」／ボタン「トップへ戻る」。
  - 配色はサイトの紺（`#082a59`）とライム（`#c7fa42`）に合わせる。`animate-pulse` などの装飾は付けない。
- これにより未使用になる `client/src/components/ui/button.tsx` / `card.tsx` を削除し、`class-variance-authority` と `@radix-ui/react-slot` を `package.json` から外す。`.github/dependabot.yml` の `ui` グループからも該当 2 行を外す。
- `client/src/lib/utils.ts`（`cn`）は `ErrorBoundary` が使うため残す。

### BUG-07 予算内候補 0 件の防御

- `suggestSet` の戻り値の型は変えない（`fore` / `back` を nullable にすると画面全体に波及するため）。
- 代わりに、フォールバックへ到達しないことをデータ側の不変条件としてテストで保証する：「`BUDGET_LIMITS` の全予算で、`withinBudget` を満たすラバーが 2 件以上ある」。
- `recommend.ts` のフォールバック行に、この不変条件とテストの場所を示すコメントを 1 行足す。

## 7. リスクと割り切り

- **BUG-03 は保存データを削除する変更である。** ラバー ID を後から変更すると、利用者のお気に入りが黙って消える。対策として「公開済みの ID は変更・削除しない」をデータ追加時のルールにする（実装ログの申し送りへ記載）。廃番の扱い（`discontinued` フラグ等）はデータ構造の設計書で決める。
- **BUG-02 の `pinnedSet` は画面内の一時状態で、保存しない。** リロードすると通常の提案表示へ戻る。
- **Step 0 の整形は差分が大きい（148 行 → 約 1,650 行）。** 単独コミットにし、整形前後でビルド成果物の JS サイズが一致することを確認する。問題があればこのコミットだけ revert できる。
- **404 画面は実質的に到達経路が少ない。** ルートは `/` のみで、GitHub Pages の `404.html` フォールバック経由でのみ表示される。作り込まない。
- ロールバック：各 Step が独立したコミットのため、該当コミットの revert で戻せる。データ移行は無い。
